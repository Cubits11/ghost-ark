Four honest verdicts. PASS = an asymmetric signature verified against a public key — this browser could not have produced it. DEV-ONLY SYMMETRIC = every check passed, but via a shared HMAC secret this browser holds, so it could forge what it just verified: consistency, never custody, and never emerald. UNVERIFIABLE = this build genuinely cannot check it. FAIL-CLOSED = a check rejected it. KMS DIGEST-mode RSA-PSS is verified here by a pure-BigInt EMSA-PSS engine (RFC 8017), because crypto.subtle always hashes the message and would double-hash a pre-hashed signature. A PASS does not prove model safety, semantic truth, compliance, chain completeness, or runtime integrity. Canonicalization is Ghost-Ark canonical JSON — not RFC 8785 / JCS, and no such compliance is claimed.
