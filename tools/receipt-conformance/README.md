# @ghost-ark/receipt-conformance

A conformance suite for Ghost-Ark decision-receipt verifiers, usable with **zero Ghost-Ark
code**: implement a verifier from [SPEC.md](./SPEC.md) alone, then check it against 36
committed vectors.

```bash
node run-conformance.mjs -- <command that runs your verifier>
# e.g.
node run-conformance.mjs -- python3 my_verifier.py
```

The harness scores three levels and never counts an unevaluated level as passed:

| level | what it asserts | evaluated when |
|:---|:---|:---|
| verdict | exit code matches the expected accept/reject on all 36 cases | always |
| failing-check | on each of 30 rejection cases, the *declared* check is among the failed | candidate prints a JSON `checks` array |
| identity | recomputed `receipt_id` / `digest_sha256` match 4 committed identities | candidate prints a JSON `recomputed` object |

What is in the suite: the 30-fixture adversarial corpus with the expected failing check per
fixture (including two validly-signed fixtures that MUST be **accepted** — they document that
signing does not make a payload true); 3 valid reproducibility fixtures; canonical-payload
vectors for checking a canonicalizer before touching cryptography; and the two RSA-PSS digest
treatments as separate vectors, each asserted in both directions. Every secret is a published
dev-only test vector, not a credential. The machine-readable contract is
[conformance.json](./conformance.json).

## Why

Ghost-Ark's E14 experiment delegated all cryptography to OpenSSL and CPython and still could
not close its independent-implementation gap: the *rule sequencing* was authored inside the
repository, so every existing verifier implements it from the same reading. This suite
externalizes the rules so an implementation can exist that never read them from Ghost-Ark
code — and so that verdict-level agreement can no longer hide rule differences. (It already
caught one: Ghost-Ark's own third-party-primitives arm is verdict-conformant 36/36 but
rejects three fixtures for the wrong reason, which the failing-check level reports.)

## Non-claim

Passing this suite establishes that a verifier reaches the declared verdicts on these
fixtures under the declared options. It does not establish correctness outside the suite,
completeness of the rules, freedom from shared misreadings between the specification and its
reference implementations, or anything about the truth of any receipt, model safety,
compliance, or AWS behaviour. The suite **narrows** Ghost-Ark's open gap #10 (no third-party
reimplementation) by making it externally closable; it does not close it, and nothing written
by the Ghost-Ark authors can.

## Regenerating

`conformance.json` and `fixtures/` are generated by `build-conformance.mjs` from the
repository's pre-registered manifests and are never hand-edited;
`tests/unit/conformance/conformanceArtifact.test.ts` fails if the committed artifact differs
from a fresh generation.
